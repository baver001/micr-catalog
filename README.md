# micr.fun — production catalog

`micr-catalog` is the production source for [micr.fun](https://micr.fun): a registry-driven catalog of independent installable micro-apps.

## Current structure

- `data/graph.json` — canonical catalog content: title, description, category, links and canonical URL.
- `data/surfaces.json` — runtime metadata: preview mode, external origin, PWA and Micr Shell policy.
- `index.html` + `data/js/catalog-hub.js` — catalog hub rendered from the registry.
- `cells/<category>/<slug>/` — canonical local app sources.
- flat `/<slug>/` routes — generated deployment links to canonical cells.
- `cells/<category>/index.html` — registry-driven category pages.
- `data/js/micr-shell.js` — shared mobile-first navigation sheet for local PWAs.
- `data/previews/` — committed RU/EN preview screenshots generated by `npm run previews`.
- `play/` — compatibility previews for external-origin apps.
- `infra/` + `.github/workflows/` — quality-gated VPS deployment.

## Local workflow

```powershell
cd D:\02_Projects\Micr\catalog
npm run dev
```

Useful checks:

```powershell
npm run check:static
npm run check:registry
npm run check:previews
npm run check:i18n
npm run check:deploy
npm run previews
```

`npm run previews` requires the Playwright CLI on `PATH`; it captures every local registry app in RU and EN at `?preview=1` without mounting the navigation shell over the preview.

## Publishing

Pushes to `main` run the quality gate. Production deploys to the VPS only when the `production` environment is configured and `DEPLOY_ENABLED=true`. The deploy script synchronizes the catalog, recreates flat app/category routes and verifies the public HTTP/API endpoints.

See [ARCHITECTURE.md](ARCHITECTURE.md) and [DEPLOYMENT.md](DEPLOYMENT.md).

## Boundaries

This repository is the personal production catalog, not the universal Micr engine. External-origin apps remain owners of their own runtime. A canonical engine upstream has not been confirmed, so no new engine repository is created automatically.
